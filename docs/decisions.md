## Decisions

### D1 – Brand lives in one place
`RequestTracer\Support\Brand` holds the name, header, gate name, log channel, mask string and storage directory.
Renaming = change `composer.json` `name`, find-and-replace the `RequestTracer\` namespace, edit `Brand`.
Config file (`config/request-tracer.php`), route prefix (`/request-tracer`), view namespace and cache keys derive from `Brand::NAME`.

### D2 – Extra span types
The brief lists twelve span types. Roots need their own: `request`, `command` (artisan + scheduled task). `job` already exists. They are documented as part of the span model.

### D3 – Decision to record is made early, confirmed late
Watch-list recording needs the authenticated user, which only exists after the session middleware. A request is therefore
either `off`, `tentative` (recorded into memory, kept only if a user matching the watch list or the sampling rules authenticates) or `on`
(signed token, local environment, `always` mode). Tentative requests that never confirm are discarded in `terminate()` with no write. A tentative recording only
happens when the watch list is non-empty or sampling is enabled, so the default production cost of an unrelated request is one header check.

### D4 – Recording default
`mode = null` resolves to `always` in `local_environments` and `triggered` everywhere else (brief: "Recording default on production: OFF").
The dashboard shows the active mode and a `production` badge.

### D5 – Storage payload encoding
Payloads (`input`, `output`, `result`, `before`, `after`) are JSON; when larger than `compress_over_bytes` they are stored as `gz:` + base64(gzip(json))
in a `longText` column. Binary columns were rejected: `bytea` (PostgreSQL) and `varbinary` (SQL Server) need driver-specific parameter binding, text is portable
to all four supported engines.

### D6 – Span identity
`tracer_spans.id` is a per-trace integer; the primary key is `(trace_id, id)`. This keeps `parent_id` valid inside one bulk insert without reading back auto-increment values.

### D7 – Extra columns
Added beyond the brief, all nullable: `tracer_traces.tables_read` (json: table → queries/rows), `tracer_traces.kind` (`request|job|command|schedule`),
`tracer_traces.parent_trace_id` (job → dispatching trace), `tracer_traces.mode`, `tracer_traces.environment`, `tracer_writes.transaction`
(`none|committed|rolled_back|open`), `tracer_writes.rows` (affected row count where known), `tracer_spans.count`/`total_us` for collapsed spans, `tracer_spans.meta`.

### D8 – Row counts for tables that were only read
`QueryExecuted` does not carry a result count. Eloquent `retrieved` events are counted per table (cheap, no span), so the dashboard shows
real row counts for rows hydrated through Eloquent and query counts for everything else. Documented as a limitation.

### D9 – Events
The Laravel event dispatcher offers no before/after-listener hook; replacing the `events` instance is unsafe (the router, DB connections and Eloquent hold the original).
Event spans are recorded from a wildcard listener (which Laravel runs after the specific listeners), together with the introspected list of listeners.
Work done *by* listeners appears as sibling spans just before the event span; listeners that are classes in a proxied namespace get their own `handle` span (layer 2).
Documented in "How capture works".

### D10 – Proxies hook into the container with `beforeResolving`
For a class in a configured namespace the container binding is replaced (keeping the shared flag) by a closure that builds the generated subclass through the container,
so the parent constructor receives its dependencies. Contextual bindings are copied to the proxy class. Classes bound to custom closures, final classes,
and objects created with `new` cannot be proxied; the dashboard says so ("not traceable: final").

### D11 – Deep trace compiles by source edits, not by pretty printing
`nikic/php-parser` is used only to find node positions (`startFilePos`/`endFilePos`); probes are inserted as text edits on the original source.
That keeps every original line, comment and whitespace untouched, so line numbers are identical by construction and the diff is minimal. It works the same with php-parser v4 and v5.

### D12 – No closures in config
`config:cache` cannot serialize closures. Resolvers (tenant, module) and custom storage drivers are class names; closures can be registered from a provider through the `Tracer` facade.

### D13 – "Not run" is only shown on lines that carry a probe
Deep trace stores the probes that were hit, never the ones that were not. Marking every code-looking line without a row as "not run" was wrong for the continuation lines of a multi-line statement.
The span-lines endpoint therefore compiles the function again (read only, nothing is written) and returns the probe lines as `statements`; the dashboard marks only those. If the file cannot be compiled the dashboard falls back to a text heuristic.

### D14 – The dashboard has no router and no UI library
The app is a few screens, so it uses the History API directly (`<base>/trace/<id>`) and a small store. That keeps the committed `dist/` at about 140 KB (51 KB gzip), and the only runtime dependency is Vue.
