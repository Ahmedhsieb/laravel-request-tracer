# Request Tracer

[![الإصدار](https://img.shields.io/packagist/v/ahmedhsieb/laravel-request-tracer.svg)](https://packagist.org/packages/ahmedhsieb/laravel-request-tracer)
[![الاختبارات](https://github.com/ahmedhsieb/laravel-request-tracer/actions/workflows/ci.yml/badge.svg)](https://github.com/ahmedhsieb/laravel-request-tracer/actions/workflows/ci.yml)
[![الرخصة: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**استبدل `dd()` بتتبّع كامل للطلب.**

عندما يتصرّف طلب بشكل غريب، يعرض لك `dd()` قيمة واحدة في مكان واحد ثم يقتل الطلب. أما Request Tracer فيسجّل **الطلب كاملاً** على شكل شجرة، ويتيح لك النظر داخل كل خطوة:

- **المسار (Flow):** الـ middleware والـ controller والتحقق (validation) والخدمات والاستعلامات واستدعاءات HTTP والأحداث والـ jobs والاستثناءات، مع شريط زمني لكل خطوة.
- **المدخلات والمخرجات** لكل خطوة، بنفس تنسيق `dd()`.
- **داخل الكود:** سطراً بسطر، أي شرط كان صحيحاً أو خاطئاً، وأي كتلة نُفّذت، وماذا كانت قيم المتغيرات، مع أرقام الأسطر الأصلية وزر إعادة التشغيل (Replay).
- **قاعدة البيانات:** كل جدول كتب فيه الطلب، مع الصف قبل التغيير وبعده.
- **المشاكل:** الاستثناءات التي تم التقاطها، واستعلامات N+1، والاستعلامات المكرّرة أو البطيئة، والخطوات البطيئة، واستدعاءات HTTP الفاشلة.

## خطوتان فقط

```bash
composer require ahmedhsieb/laravel-request-tracer

php artisan request-tracer:listen
```

هذا كل شيء: لا ملف إعدادات، ولا migration، ولا شيء تنشره (publish). الجداول تُنشأ تلقائياً عند أول استخدام ولوحة التحكم تُقدَّم من الحزمة نفسها. استخدم تطبيقك كالمعتاد ثم افتح `/request-tracer`.

الأمر `request-tracer:listen` يعمل مثل `queue:work`: **طالما هو شغّال** يُتتبَّع كل ما يفعله المشروع (الطلبات، والـ jobs، وأوامر artisan، والمهام المجدولة)، ويُطبع كل تتبّع في الطرفية فور حفظه. اضغط Ctrl+C فيتوقف التسجيل خلال ثوانٍ. **وعندما لا يكون شغّالاً لا يُسجَّل أي شيء**، وتكلفة الحزمة حينها من 25 إلى 65 ميكروثانية للطلب.

### أي كود يُتتبَّع؟

**كل مجلد `app/`**: كل استدعاء بمدخلاته ومخرجاته، وسطراً بسطر كل شرط وكتلة ومتغيّر. لا تحتاج إلى كتابة أسماء الأصناف. ولتتبّع مجلد آخر أو ملف واحد، أو لاستثناء شيء معيّن:

```php
// config/request-tracer.php   (php artisan vendor:publish --tag=request-tracer-config)
'code' => [
    'paths' => ['app', 'modules/Billing/src', 'lib/Money.php'],   // مجلدات أو ملفات، نسبةً إلى المشروع
    'except' => ['app/Legacy', 'App\Reports\*'],                   // هذه فقط تُستثنى؛ وما عداها يُتتبَّع
],
```

### طلب حدث بالفعل

لم يكن أي شيء يسجّل وقتها؟ **شغّله مرة أخرى مع التتبّع.** في لوحة التحكم: *Replay a request* ثم الصق أمر cURL (من المتصفح: تبويب Network ثم *Copy as cURL*)، أو اضغط *Replay this request* على تتبّع موجود. ومن الطرفية:

```bash
php artisan request-tracer:replay "POST /orders" --data='{"items":[1,2]}' --as=42
```

ينفّذه التطبيق كأنه جاء من الخارج، و**أنت تختار ما يجوز له أن يغيّره**. **المحاكاة** (الافتراضي) لا تغيّر شيئاً: تُلغى تغييرات قاعدة البيانات (rollback)، ولا تخرج رسائل البريد ولا الإشعارات ولا الـ jobs ولا استدعاءات HTTP client الخاصة بلارافيل. أما **التشغيل الفعلي** فيترك الطلب يفعل ما يفعله، ويسجّل كل كتابة Eloquent بدقة لتستطيع **التراجع** عنها بعد ذلك (`php artisan request-tracer:undo <trace>` أو الزر في صفحة الـ trace). الكتابات بالـ query builder أو بـ SQL خام، والبريد، والاستدعاءات الخارجية، والملفات لا يمكن التراجع عنها، واللوحة تقول ذلك صراحةً. هذا الأمر مُعطَّل في بيئة production ما لم تفعّله، والتشغيل الفعلي هناك يحتاج `replay.real` أيضاً.

### لا تعرف شكل الطلب؟

فعّل **سجل الطلبات** (`REQUEST_TRACER_JOURNAL=true`). يسجّل كل طلب في سطر واحد خفيف (الـ URL، والبودي بعد إخفاء الأسرار، والمستخدم، والحالة، والخطأ)، سواء تُتبّع أم لا، لمدة ساعة. في تبويب *Journal* في لوحة التحكم اختر الطلب الذي فشل فيُعاد تشغيله بنفسه: نفس الـ URL ونفس البودي ونفس المستخدم، مع تتبّع كامل. ومن الطرفية: `php artisan request-tracer:replay --journal=failed`. هو مُعطَّل افتراضياً لأنه يحتفظ بأجسام الطلبات لمدة ساعة؛ والأسرار تُخفى قبل تخزينها.

### في الإنتاج

الخطوتان نفسهما على الخادم. ولوحة التحكم تبقى مغلقة حتى تحدّد من يحق له فتحها:

```php
Gate::define('viewRequestTracer', fn ($user) => in_array($user->email, ['ops@example.com']));
```

تُخفى الأسرار قبل التخزين، وأي عطل داخل المتتبّع لا يكسر الطلب أبداً. ويمكن أيضاً تتبّع طلب واحد دون الأمر: بترويسة موقّعة أو بمراقبة مستخدم أو بأخذ عيّنة.

## المتطلبات

PHP 8.1 أو أحدث، وLaravel 10 أو 11 أو 12 أو 13، وقاعدة بيانات MySQL / MariaDB أو PostgreSQL أو SQLite لحفظ التتبّعات. تعمل مع Octane ومع عمّال الـ queue. ولتجربة اللوحة ببيانات تجريبية ودون خادم خلفي: `npm ci && npm run dev`.

## التوثيق

التوثيق الكامل بالإنجليزية في مجلد [docs](docs/01-introduction.md): المقدمة، التثبيت، البدء السريع، مرجع الإعدادات، آلية الالتقاط، التتبّع العميق (Deep trace)، التشغيل في الإنتاج، التطبيقات الكبيرة وأنظمة ERP، استخدام لوحة التحكم، الـ jobs والأوامر والمهام المجدولة، التوسعة، المقارنة مع الأدوات الأخرى، وحل المشاكل.

## ما التكلفة؟

لا شيء يمكن قياسه عندما لا يستمع أحد (من 25 إلى 65 ميكروثانية للطلب). وأثناء الاستماع يستغرق طلب من 47 خطوة و15 استعلاماً نحو 5 مللي ثانية إضافية مع مدخلات ومخرجات كل استدعاء، ونحو 7.5 مللي ثانية مع كل سطر، ثم من 7 إلى 10 مللي ثانية بعد إرسال الاستجابة. طريقة القياس والتحفّظات في [docs/benchmarks.md](docs/benchmarks.md).

## حدود يجب معرفتها

لا تستطيع الـ proxies رؤية `new` ولا الأصناف `final` ولا الدوال الخاصة (private) أو الساكنة (static). التتبّع سطراً بسطر يترجم نسخة من كل ملف في `code.paths` عند تحميله لأول مرة أثناء الاستماع (PHP-FPM و`artisan serve` يحمّلان الأصناف مع كل طلب فيعملان مباشرة، أما العامل طويل العمر مثل Octane أو `queue:work` فيحتفظ بالأصناف التي حمّلها قبل أن تبدأ الاستماع إلى أن يُعاد تشغيله). إخفاء الأسرار يعتمد على الأسماء. والحزمة ما زالت في الإصدارات `0.x`.
